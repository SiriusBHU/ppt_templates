# 把已有 PPT 页抽象成模板

输入是一份 pptx：可以是用户给的样板，也可以是公司内部真实页经 `tools/ppt-skeleton` 脱敏后带出的骨架稿（随附 `manifest.yaml`）。输出是 `templates/<topic>/<template>/` 下的 `template.yaml`、`example.yaml`、`preview.png`。仓库规则以 `AGENTS.md` 为准，本 skill 只描述流程和踩过的坑。

## 三条原则

1. **先讲清这一页的逻辑，再做版式。** 模板要还原的是原页「每个元素承载什么、它们怎么组成一个完整的论证」：左边的文字讲什么、右边的文字讲什么，这个框是为了把哪些文字圈在一起、那个框是给架构图占位，上下是层次关系还是先后关系，颜色和图例代表什么。这些写进 `template.yaml` 的 `structure`，槽位、`description`、example 的引导文字都要和它一一对上。不能把原页泛化成「分组名称（一）」「左栏小节标题」这样的卡片网格。
2. **样式照原页。** 描边还是阴影、圆角还是直角（含圆角大小）、底色、文字对齐、加粗、文字颜色都照原页；只有颜色和字号换成最接近的 token（`ppt import` 已经给出）。`AGENTS.md` 的风格约定只用在原页没交代的地方。
3. **模板要能复用。** 模板讲的是「这一类页」，不是这一份原页：原页的业务词（某某建模仿真、领域名、产品名）不能写进模板名、`structure`、描述和固定文字；原页的具体数量（三层、第一层只有一张卡、三大特征）变成数量范围（`minItems` / `maxItems`），排布用 grid 按数据排，不逐行写死。原页的通用叫法（接口专家、核心问题、关键举措）可以保留。

## 必需环境：LibreOffice

导入原图、模板预览、还原对照都靠 LibreOffice（`soffice`）出图。**它是本 skill 的必需依赖，不是可选项**：

- 开始前先检查：`uv run ppt preview common.cover-basic -o out/env-check`。生成了 PNG 就是装好了；报「找不到 soffice」就是没装。
- 没装就先安装，装好再继续：
  - Windows：`winget install --id TheDocumentFoundation.LibreOffice -e`（装到默认位置即可，`ppt` 会自己找到，不用改 PATH）
  - macOS：`brew install --cask libreoffice`
  - Linux：用发行版的包管理器装，如 `sudo apt install libreoffice-impress`
- 安装会改动系统：按所在环境的规则先告诉用户、得到同意后再装。装不了（没有权限、用户不同意）就停下来说明原因，不要往下做。
- 装好之前不要开始写模板：不能跳过出图、只凭 `shapes.yaml` 写模板，也不能省掉预览和还原对照。`ppt import` 提示「没有生成 original.png」时，同样先装好再重新导入。

## 准备

- 在仓库根目录（含 `taxonomy.yaml`）运行 `uv run ppt ...`；第一次先 `uv sync`。
- 样板放在 `samples/`（目录里的文件都被 `.gitignore` 忽略），连同 `manifest.yaml` 一起，永远不要提交。
- 模板语法从这三处查就够了：`AGENTS.md` 的结构约定、`schema/template.schema.json`（layout 元素的全部字段）、2–3 个版式相近的现有模板（按这三条原则做的范例：`product.roadmap-capability-map`、`project.roadmap-workstreams`、`workload.problem-chart-cases`、`solution.solution-dual-metrics`）。不用读 `src/` 的渲染和校验代码；用组件时只看组件文件开头的模块说明、`SCHEMA` 和 `PROPS_SCHEMA`。

## 流程

1. **导入。** `uv run ppt import <pptx> [--slide N ...] -o <临时目录>`，每页得到 `original.png` 和 `shapes.yaml`（逻辑像素坐标、最接近的颜色和文字 token、对齐、阴影、描边、圆角 `radius`、`frame_guess`、图片位的 `suggest: image`）。先看原图理解内容，再从 `shapes.yaml` 取尺寸、比例和样式。
   - 原页里如果有「这页该做成什么模板」的标注框（常见是黄色矩形，写着结构说明）：它是元信息——用它理解结构意图，**不做进模板**；被它遮挡的文字从 `shapes.yaml` 找回（含全部形状的文字）；标注的描述和原页冲突时，以原页和 `shapes.yaml` 为准。注意 `ppt leaks` 会把标注框文字也算作原文，模板的固定文字和引导文字要避开它的措辞。需要干净的对照图时，可以用 python-pptx 删掉标注形状再渲染一版放在 `out/`。
2. **写 `structure`。** 每个区块一条，写「元素：角色 / 作用」，最后一条写它们之间的关系：
   - 文字块写它讲什么（主题、层次名、工作项名、一段说明讲哪几件事、谁对接……）；框写它为什么存在（圈住一个工作项的名称 + 说明 + 负责人 / 给架构图占位 / 标出所属分组）。
   - 关系写清楚：左右一一对应、上下是层次还是先后、同一行是并列还是递进、哪段是哪段的总结、颜色和图例分别代表什么。
   - 用原页自己的概念命名（层次、工作项、接口专家、核心问题……），但不写具体业务内容。
   - 写这一类页的规律，不写这一份原页的排布：写「每层一到四个工作项，说明多的卡可以加宽、两张短卡可以上下叠」，不写「第一层只有一张卡、第二层第三列叠两张」。
   - 标题是主题式（名词短语）还是结论式（一句判断）照原页，写进 `structure` 和 `title` 的 `description`。
3. **定归属。** 对照 `taxonomy.yaml` 和 `catalog.json`，给每页定主题、页功能（`roles[0]` 决定目录名）和处理方式：替换已有模板（同一页做过的模板直接替换）、新增，或只给已有模板加 `also_fits`。列成表给用户确认后再动手；真正拿不准的只问一个问题。
4. **拆成槽位和元素。** `structure` 的每一条都要落到槽位上，槽位名和 `description` 用 `structure` 里的概念。
   - 标题：原页没有副标题行时只写 `title`，不写 `title_suffix` / `takeaway`（`frame: standard`，正文自动用 `body_compact`）。现有模板大多带这两个槽位，不要照抄。
   - 先找组件，能还原原页结构（嵌套分组、通栏条目、分类底色）就用组件：

     | 原页里是 | 用 |
     |---|---|
     | 表格、指标前后对比 | `table` |
     | 能力地图 / 业务沙盘：分组面板 + 子能力格，组里还有带标题的分组框，条目分两类底色 + 图例 | `capability-map` |
     | 分层架构：左边层名、右边模块 | `layered-arch` |
     | 几个竖向分区并排，可选共享层横跨 | `partitioned-arch` |
     | 泳道路线图：时间轴 × 产品线 | `lane-roadmap` |
     | 框图 / 流程图：节点 + 箭头 | `block-diagram` |
     | 重复的卡片、行、列 | `grid`（可嵌套，序号用 `#`） |

     都不合适就新增组件（照 `src/ppt_templates/components/partitioned_arch.py`：`SCHEMA` 只管结构、`PROPS_SCHEMA`、`check` 与 `render` 共用一个 `_plan`、中文报错、配测试），不要在模板里堆 shape。
   - 行高、卡片宽度随内容变化（原页各行不等高、卡片不等宽）→ grid 的 `weight`（`height` / `width` 槽位，带 `minimum` / `maximum`）；同一列上下叠两张卡 → 内层 `grid`。
   - 颜色、图例承载的分类 → 条目加 `enum` 字段，用 `fill_map` / `color_map` 或组件的 tag 映射到颜色 token，并保留图例。
   - 一张卡里并列的几段说明（不带项目符号）→ `bullets` + `marker: false`；带项目符号的「名称：说明」要点 → `bullets` 的项写 `{name, text}`，句尾的蓝色强调写进 `highlight`；「小节标题 + 它的要点」一节接一节往下排 → `bullets` 的 `children`（不要用 grid 等分高度）；单独一行的「名称：说明」→ `runs`；图片、图表、截图 → `image`，`placeholder` 写清该放什么图；叠在图上的标注 → 在 `image` 后面放元素盖在图上，颜色随数据变就用 `by` + `color_map`。
5. **写模板。**
   - 样式照原页：

     | 原页 | 写成 |
     |---|---|
     | 细描边、无阴影的框 | `fill: bg`（或原底色的 token）+ `line: line`，不写 `shadow`；虚线框加 `dash: true` |
     | 带阴影的框 | `shadow: true`，描边照原页 |
     | 圆角框 | `shape: rounded` + `radius`（取 `shapes.yaml` 的 `radius`，同类框取一个整数） |
     | 灰底 / 浅灰面板 / 浅蓝强调底 | `surface` / `surface_light` / `highlight_blue` |
     | 居中 / 左对齐 | 照原页写 `align`；卡片里的说明顶对齐（`valign: top`） |
     | 蓝 / 深红 / 黑字 | `primary_text` / `accent` / `text`，原页什么颜色就用什么（黑字不要为了强调改成深红） |
     | 字号、加粗 | 取最接近的 token，加粗照原页：24 加粗 `title`；18 加粗 `heading`、18 常规 `subtitle`；14 加粗 `emphasis`、常规 `lead`；12 加粗 `body_strong`、常规 `body`；10 `detail`；9 `caption` |
     | 组件画出来的样式和原页不一样 | 用组件的 `props` 调：表格白底横线 `look: plain` + 数据里的 `widths`；能力地图的外框、面板底色、组名颜色、条目底色、图例画法（见 `AGENTS.md`） |

   - `subtitle`（18 号常规）不能当卡片标题；卡片标题加粗、放在卡片里面。
   - **字数上限按框算**：一个中文字宽 24 号 32px、18 号 24px、14 号 18.7px、12 号 16px、10 号 13.3px，英文、数字约半个字；行高约为字宽 × 1.3（12 号 21px）。每行字数 = ⌊框宽 ÷ 字宽⌋，行数 = ⌊框高 ÷ 行高⌋，`maxLength` ≈ 每行字数 × 行数 × 0.9。名称、卡片标题这类短语必须一行放下。项数不同、卡片宽度不同时用 `if` / `then` 分别给上限。原页的真实内容应该放得下（第 6 步会验证）。
   - **`example.yaml` 写引导文字**：每个字符串用 `structure` 里的角色说明「这里该填什么」（「第一层的层次名称」「工作项名称（点出建的是什么）」「写清对象和方法、做到的精度，以及支撑哪项决策」），不写像真实内容的句子，也不能把原页内容换个说法、换个领域词复述。每个字符串写到上限的八成左右，按实际行宽凑成整行（不留只折下一两个字的行）；可选字段也填上，条目数、行高、宽度取原页的；图片槽位留空。
6. **校验和对照。**
   - `uv run ppt validate` → `uv run ppt leaks <id> <样板.pptx> --slide N`（同时查 `template.yaml` 和 `example.yaml`，必须 0 处；只有原页的通用叫法，如「核心问题」「接口专家」，才能 `--allow`，并在汇报里列出；业务词要换成通用说法）→ `uv run ppt preview <id> --write`。
   - **还原对照**：把原页的原文按槽位填成一份 deck，放在 `out/`（不提交），`uv run ppt preview <deck> -o out/...`，和 `original.png` 并排看——结构、样式、比例、颜色应该几乎一样；原文放不下，说明上限或版式不对，回去改。原页的手绘架构图 / 示意图在模板里是 `image` 槽位：还原时从 `original.png` 裁对应区域（1920×1080 = 画布 1280×720 的 1.5 倍）存到 `out/` 填进 deck，这样图上部分也能对比。
   - 逐条检查下面七项，任何一项不满足就改了再看：
     1. 语义：`structure` 覆盖了原页每个区块和它们的关系；槽位名、`description`、引导文字都用这些概念，没有泛化；没有原页的业务词，数量是范围而不是原页的个数。
     2. 结构：每个区块、每组重复结构、嵌套分组、图例和分类底色在预览里都有对应。
     3. 样式：描边 / 阴影、圆角、底色、对齐、加粗、文字颜色和原页一致（还原对照图里看）。
     4. 填充：引导文字预览里每个框基本写满，没有只折下一两个字的行，页面底部没有大块空白。
     5. 溢出：两张图里都没有文字超出框、压到别的元素、被截断；名称和卡片标题都是一行。
     6. 间距和对齐：段与段、卡与卡之间有间距；同一行卡片的标题、说明、底部行各自对齐。
     7. 示例：全是引导文字，`ppt leaks` 是 0 处。
7. **收尾。** `uv run ppt catalog`、`uv run ppt validate`、`uv run pytest`。把「原图 | 原文还原 | 引导文字预览」三张对照图发给用户；汇报里写七项各自的结论（满足 / 不满足 + 说明，不要笼统地写「无问题」），列出和原页仍有的差异，以及需要用户拍板的取舍。用户说提交才提交。

## 一次做多页

- 先把多页共同需要的渲染器能力（新元素、新 token、页框变化）单独做完，再每页一个独立子任务并行写模板。
- 并行时只允许一个任务改 `src/` 和 `AGENTS.md`；其余任务只动自己的模板目录、不运行 `ppt catalog`，忽略别的目录尚未完成造成的校验错误。全部完成后统一跑 catalog、validate、pytest。

## 踩过的坑

- 把原页泛化成通用卡片网格：层次名变「分组名称（一）」、栏目标题变「左栏小节标题」、图例变「第一类 / 第二类」、标注和注释被删掉 → 先写 `structure`，按它命名、按它检查。
- 套用「白底阴影卡片、直角、左对齐」的默认风格，把原页的描边框、圆角、灰底、居中都改掉了；或把原页的黑字改成深红 → 样式照原页，默认风格只补原页没交代的地方。
- 过拟合原页：模板名叫「某某建模仿真规划」、每个层名下面固定写原页的工作类型、按原页的三行逐行写死版式 → 换个领域就用不了；业务词换成槽位或通用说法，排布用 grid 按数据排。
- 为了「写满」把原页内容换个领域词复述进 example → 这就是泄露，`ppt leaks` 会报；改成说明该填什么的引导文字。
- 照抄现有模板的 `title_suffix` / `takeaway`，把原页的一句标题拆成短标题 + 副标题；或者把主题式标题改成结论句 → 标题照原页。
- 行高均分、卡片等宽，原页内容多的行放不下、内容少的行空着 → 用 grid 的 `weight`。
- 说明文字用 `valign: middle`，同一行几张卡的说明上下错开 → 顶对齐。
- 大卡片里放固定高度的小文字框，卡片下半截空着；`maxLength` 压得太低、example 写得太短 → 按第 5 步的算法让框和字数互相匹配，再用原文还原对照验证。
- 圆角不写 `radius` 时随框变大，大卡片会切到角上的文字 → 写 `radius`。
- `table` 组件字号固定 12 号、单元格左右各留 12px，框窄列多时每格放不下几个字（可放字数 ≈ (框宽 ÷ 列数 − 24) ÷ 16） → 长内容挪到要点里，或在汇报里提出来；原页表格是内嵌截图、有合并单元格、或窄列配长英文 / 数字时，直接降级为 `image` 槽位（截图表格就保持截图）。
- 「✓ 红 + 红色名称 + 黑色说明」这类逐段着色的要点 `bullets` 表达不了（marker 只有 •、名称和正文只能同色）→ 用嵌套 grid + `runs`；`runs` 里 `bind` 取不到值的 run 会跳过，可以做成可选的强调片段。
- 预览把微软雅黑固定替换成冬青黑体，比雅黑宽约 10%：`maxLength` 按公式算完要留余量，并以还原实测为准校准，别卡着公式上限写。
- 原页内容超出标准页边距（`frame_guess: none`、元素越出 body 区）很常见：模板仍归 `frame: standard`，把内容收敛进 body 区重排比例；整句 24 号标题在标题框里放不下就拆 `title` + `title_suffix`（18 号后半句）。
- 渲染器表达不了的装饰（圈码①②③、列间竖分隔线、大括号、手绘图上叠注、合并表头）不要硬凑：用 grid `#` 编号、上下对齐等结构性手段表达对应关系，剩余差异在汇报里列出来。
- 长英文单词放不进窄框会被拦腰折断 → 组件的 `check` 要拦住，示例里少用长英文。
