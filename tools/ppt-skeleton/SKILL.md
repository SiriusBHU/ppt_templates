# PPT 页脱敏成骨架

把选定的几页变成「只剩版式」的 `.pptx`：版面、字号、配色、结构全部保留，文字变成引导性描述，不含任何项目信息。三个命令：`extract` 提取文字 → 你填引导文字 → `apply` 生成骨架 → `check` 审计泄露。

## 准备

- 需要 Python 3.8+ 和 `pip install python-pptx`，别的都不用装。
- 把整个 `ppt-skeleton/` 目录复制到 Agent 的 skills 目录（Claude Code：`~/.claude/skills/ppt-skeleton/` 或项目内 `.claude/skills/ppt-skeleton/`；Codex、Cursor 等放各自的 skills 目录）。
- 下文 `SK` 指 `python3 <本 skill 目录>/scripts/skeleton.py`（Windows 用 `python`）。
- 可选：装有 LibreOffice（`soffice`）时，`render` 能生成 PNG 预览。

## 流程

1. **问清三件事**：原 PPT 路径；要处理哪几页（页码从 1 起，如 `1,3-5`，输出按给定顺序排）；敏感词文件。敏感词文件一行一个词，写项目代号、客户、产品 / 芯片 / 平台名、内部系统名、人名、部门等；用户没有就帮他列一个 `sensitive.txt`。敏感词文件和 `WORK_DIR` 都放在要带出的文件之外。
2. **提取**：`SK extract IN.pptx --slides 1,3-5 -o WORK_DIR`。生成：
   - `texts.json`：原文，每条有 `id`、`location`、`kind`、`text`、`font_pt`、`chars`、`budget`（建议字数范围）、`box_pct`（位置占页面的百分比 `[x,y,w,h]`）。
   - `replacements.json`：`{id: ""}`，你来填。
   - `manifest.yaml`：每页一个 `purpose`，你来填。
3. **填写**：读 `texts.json`，给 `replacements.json` 的每个 id 写引导文字（规则见下），给 `manifest.yaml` 每页写一句通用用途，例如「系统方案总览：挑战、理念、架构图、关键技术」。
4. **生成并审计**：
   ```
   SK apply IN.pptx WORK_DIR -o OUT.pptx
   SK check IN.pptx OUT.pptx WORK_DIR --words sensitive.txt
   ```
   `check` 必须以 0 项问题结束；有问题就改 `replacements.json` / `manifest.yaml`，重新 `apply` 再 `check`。`--allow 词` 只用于用户明确确认无害的通用词（如「关键技术」），可重复使用，报告里会列出这些词。`OUT.pptx` 不能写进 `WORK_DIR`。
5. **目检（可选但建议）**：`SK render OUT.pptx -o DIR`，用 Read 看 PNG，对照原页确认版面没变；字数太多的地方会溢出，回去改引导文字。
6. **交付并提醒用户**：可以带出的只有 `OUT.pptx` 和 `manifest.yaml`。明确说：**不要带出 `WORK_DIR/texts.json`（含原文）、`replacements.json`、敏感词文件和原 PPT**；带出前请用户自己逐页打开 `OUT.pptx` 看一遍，并确认带出符合公司的信息安全规定。`check` 通过只说明工具能查到的都清掉了，不代表可以免于人工复核。

## 引导文字怎么写

描述这段文字**是什么角色、该写什么**，而不是原来写了什么。

| 原文是 | 写成 |
|---|---|
| 页标题 | 「标题：本页结论或主题」 |
| 小节 / 栏目标签 | 「小节标签」「栏目名称」 |
| 条目名（带说明，如「100M长序列：KV Cache 随序列线性增长」） | 「挑战名称（短语）：现象 + 量化影响」 |
| 一句说明 | 「说明句：做法 + 效果」 |
| 数值、指标 | 「N」「N%」「N 倍」「XX 毫秒」 |
| 模块 / 组件 / 角色名 | 「模块名称」「角色 A」 |
| 产品、客户、芯片、项目名 | 「产品 A」「客户」「芯片 A」「项目」 |
| 表头 | 「指标名称」「当前水平」（纯通用列名可保留） |

规则：

- 每个 id 都要填，空的会让 `apply` 失败。
- 字数在原文的 ±20% 内（看 `budget`），保持版面密度；原文是「名称：说明」就写成「名称（短语）：说明（一句话）」，保留标点结构。
- 数字一律换成 N / XX / N%，日期写 20XX 年 / X 月；单独的序号 1、2、3 可以原样保留。
- 一切产品名、客户名、芯片型号、项目代号、公司、人名、内部系统名换成通用词。纯通用的小节标签（背景、挑战、方案、收益）在不含项目信息时可以保留。
- 不要照抄原文片段：和原文连续相同 5 个汉字或 8 个字母，`check` 就会拦下；也不要拿原文里的缩写、内部术语当「通用词」。
- 同一段里格式不同的部分（比如加粗前缀 + 常规说明）已拆成多条，`location` 里有「片段 i/n」，分别写，各自保持原来的字号和加粗。
- 一条里需要换行时写 `\n`。
- 填完 `manifest.yaml` 的 `purpose` 同样要通用，不含项目信息；值里有半角冒号时加双引号。

## 会被剥离的内容

演讲者备注、批注及作者、全部文档属性（作者、标题、公司、经理、自定义属性、缩略图）、超链接和点击动作、替代文字、形状名（改成 `Shape N`）、标签、节名和自定义放映、隐藏页状态、动画与切换、内嵌字体；图片 / 图片填充 / 背景图 → 浅灰矩形（图片写「图片」）；图表 / SmartArt / OLE / 媒体 → 同大小灰色矩形（「图表」「图示」「对象」）；母版和版式里的文字、图片、页脚 / 日期 / 页码占位符，以及没用到的版式和母版；包里所有不再被引用的部件。

## check 的规则

(a) 与原文（所有页、备注、母版）连续重合 ≥5 个汉字或 ≥8 个字母的片段，出现在 OUT、`manifest.yaml` 或 `replacements.json`；(b) 原文里 ≥3 位的数字出现在 OUT；(c) 敏感词（不分大小写）出现在包内任何位置；(d) 残留媒体、嵌入对象、图表、SmartArt、备注、批注、customXml、缩略图等部件；(e) 文档属性里的作者、公司、标题等非空；(f) 超链接关系；(g) 文字与原文完全相同；(h) `manifest.yaml` 的 `purpose` 缺失或为空。有任何一项就以非零退出码结束。

## 已知局限

- 所有图片都被整体替换，所以图片里的文字不会泄露，但也无从检测；矢量画出来的 logo（自由曲线形状）会原样保留，目检时留意。
- SmartArt、图表、OLE 只换成灰框，内部结构和数据丢失。
- 同一格式组内的多个 run 合并为一个，沿用第一个 run 的格式；组内换行需要自己写 `\n`。
- 形状的几何、颜色等视觉属性原样保留，如果它们本身就是公司专属的设计（品牌色、特有的图形），需要用户判断。
